| 项目 | 内容 |
|---|---|
| 版本 | v0.1 |

**假设说明**：

- 主要用户在中国大陆网络环境下使用
- 用户自己提供大模型 API Key，产品不搭建付费后端
- 首期只支持中文

## 1. 背景与问题

- **问题**：越来越多公司的校招第一轮是 **AI 视频面试**（如平安健康险：每题 15 秒准备、5 分钟作答，AI 根据回答追问 1–2 次，按关键词和逻辑结构打分）。求职者没有地方针对性地练习。
- **证据**：作者本人在 2026 年秋招中参加了平安健康险、携程的 AI 面试。准备时只能靠搜面经、自己写答案、对着镜子练，存在三个问题：
  1. 面经零散，很多公司搜不到具体题目
  2. 写出来的答案和**说出来**的效果差别很大，说的时候容易没有结构、超时
  3. 没有人追问，也没有人反馈哪里答得不好
- **现状**：现有的面试练习工具大多使用固定题库，不针对具体公司和岗位，也很少模拟追问。

## 2. 为什么要用 AI

| 需求 | 非 AI 方案能否解决 | 结论 |
|---|---|---|
| 计时、流程控制 | **能**，普通前端逻辑 | 不用 AI |
| 搜集公司和岗位信息 | 部分能（手动搜索） | **用 AI 联网搜索并整理**，节省时间 |
| 根据 JD 和简历出题 | 固定题库无法针对具体岗位 | **用 AI** |
| 根据回答内容追问 | 规则无法理解回答内容 | **用 AI**，这是核心功能 |
| 评价回答质量 | 规则只能统计字数、时长 | **规则 + AI 结合**：时长、字数由规则统计；结构、内容由 AI 评价 |

**用户对出错的容忍度**：中等。题目出得不够准、评分有偏差，影响的是练习效果，不会造成实际损失。但**不能把 AI 推测的题目说成"该公司真实面经"**，否则会误导用户的准备方向。

## 3. 目标用户与场景

| 用户角色 | 使用场景 | 核心诉求 |
|---|---|---|
| 校招求职者 | 收到 AI 面试通知，面试前 1–3 天准备 | 针对这家公司、这个岗位练习，知道自己哪里答得不好 |
| 社招求职者 | 准备跳槽面试 | 根据 JD 和简历预测问题 |

## 4. 目标与成功指标

| 类型 | 指标 | 目标值 |
|---|---|---|
| 用户指标 | 完成一轮完整模拟（≥ 3 题）的比例 | ≥ 60% |
| 用户指标 | 同一用户重复使用的比例 | ≥ 30% |
| AI 质量指标 | 题目与 JD 相关度（人工评审） | ≥ 85% |
| AI 质量指标 | 来源标注准确率（标为"来自面经"的题确实能在来源中找到） | 100% |
| AI 质量指标 | 追问与回答内容相关的比例 | ≥ 90% |
| 项目指标 | GitHub star | 上线 1 个月内 ≥ 50 |

## 5. 范围

**本期做**：

- 输入公司、岗位、JD（可选：简历）
- AI 联网搜索并生成题目，标注每道题的来源
- 模拟流程：15 秒准备 → 限时作答 → AI 追问 1–2 次
- 语音输入（浏览器支持时）+ 文字输入
- 每题评分和参考回答；一轮结束后的总结报告

**本期不做**：

- 录制视频、表情或语气分析
- 账号系统、云端保存记录（记录只保存在用户自己的浏览器里）
- 英文面试

## 6. 用户故事与验收标准

| 编号 | 用户故事 | 验收标准 | 优先级 |
|---|---|---|---|
| US-01 | 作为求职者，我希望输入公司、岗位和 JD 后自动生成题目，以便针对性地练习 | Given 填写公司、岗位和 JD，When 点击「生成题目」，Then 60 秒内生成 6–8 道题，覆盖自我介绍、行为题、项目题和岗位相关题 | Must |
| US-02 | 作为求职者，我希望知道每道题从哪来，以便判断准备的重点 | Given 题目生成完成，Then 每道题标注来源：🔍 检索到的面经（附链接）/ 📄 根据 JD 推测 / 👤 根据简历；Given 没有搜到面经，Then 页面提示"未检索到该岗位的公开面经，以下题目根据 JD 推测" | Must |
| US-03 | 作为求职者，我希望在开始前能删改题目，以便去掉不相关的题 | Given 题目列表，When 删除、编辑或新增题目，Then 模拟按修改后的列表进行 | Should |
| US-04 | 作为求职者，我希望体验和真实 AI 面试一样的时间压力 | Given 开始一道题，Then 先显示 15 秒准备倒计时，结束后自动进入作答，作答时长默认 3 分钟、可设置；时间到自动提交 | Must |
| US-05 | 作为求职者，我希望用说话的方式作答，以便练习口头表达 | Given 浏览器支持语音识别，When 作答，Then 实时显示转写文字；Given 不支持，Then 提示使用系统听写或打字，且打字始终可用 | Must |
| US-06 | 作为求职者，我希望 AI 像真实面试一样追问，以便练习应对深挖 | Given 提交回答，Then AI 根据回答内容追问 1–2 次，追问必须引用回答中的具体内容 | Must |
| US-07 | 作为求职者，我希望每题都有评分和改进建议，以便知道哪里答得不好 | Given 一道题（含追问）结束，Then 显示 4 个维度的评分（结论先行、结构清晰、具体数据、岗位关键词），每个维度一句理由，以及一段改进后的参考回答 | Must |
| US-08 | 作为求职者，我希望一轮结束后看到总结，以便复盘 | Given 一轮结束，Then 显示总分、最弱的维度、每题用时，可导出为 Markdown | Should |
| US-09 | 作为求职者，我希望保护我的简历和 API Key | Given 用户填写 API Key 和简历，Then 只保存在本地浏览器，不发送给除模型服务商以外的任何服务器 | Must |

## 7. AI 方案

### 7.1 AI 能力定义

| 环节 | 输入 | 输出 |
|---|---|---|
| 检索与出题 | 公司、岗位、JD、简历（可选） | 题目列表，每题附来源类型和链接 |
| 追问 | 题目、用户回答、JD | 1 个追问 |
| 评分 | 题目、回答、追问及回答、JD | 4 维评分、理由、参考回答（JSON 格式） |

### 7.2 技术方案

| 候选方案 | 优点 | 代价 | 结论 |
|---|---|---|---|
| 固定题库 | 不需要 AI，稳定 | 无法针对公司和岗位 | 作为**降级方案**：AI 不可用时使用 |
| 模型 + 单独的搜索 API | 搜索结果可控 | 用户要填两个 Key，配置复杂 | 不采用 |
| **自带联网搜索的模型** | 用户只需一个 Key | 搜索质量依赖模型服务商 | **采用** |

### 7.3 模型选择

- 需要：中文能力好、API 自带联网搜索、在国内网络下可直接访问
- 候选：通义千问、Kimi、智谱（均需技术验证，见开放问题 Q1）
- 采用 OpenAI 兼容接口，方便用户切换

## 8. 评测计划

### 8.1 离线评测集

| 项目 | 内容 |
|---|---|
| 来源 | 作者真实参加过的面试（平安健康险、携程）的公司、岗位和 JD，以及 10 个常见校招岗位的公开 JD |
| 规模 | 首期 12 组（公司 + 岗位 + JD），每组生成一轮题目 |
| 覆盖类型 | 有公开面经的大公司 / 搜不到面经的公司 / 技术岗 / 产品岗 / JD 很短的岗位 |
| 追问和评分 | 每组准备 3 个回答：好回答、一般回答、跑题的回答，检查追问和评分是否合理 |

### 8.2 指标与上线门槛

| 指标 | 上线门槛 | 一票否决 |
|---|---|---|
| 来源标注错误（推测的题标成"来自面经"） | 0 条 | ✅ |
| 题目与 JD 相关度 | ≥ 85% | |
| 追问引用了回答中的具体内容 | ≥ 90% | |
| 评分区分度：好回答的得分高于一般回答 | 12 组中 ≥ 10 组 | |
| 题目生成时间（P95） | ≤ 60 秒 | |

### 8.3 在线反馈

- 每题评分后提供"这个评分合理吗？👍 / 👎"
- 用户可通过 GitHub Issues 提交 Bad Case

## 9. 失败模式与兜底

| 失败模式 | 严重程度 | 兜底方案 |
|---|---|---|
| 把 AI 推测的题说成真实面经 | 严重 | 只有附带可访问链接的题才能标为"来自面经"；其余一律标为"推测" |
| 搜不到任何信息 | 一般 | 根据 JD 出题，并明确提示 |
| 追问与回答无关 | 一般 | 提示词要求引用回答原文；评测集检查 |
| 评分过松（什么都给高分） | 一般 | 评分标准写入提示词，并给出分档示例；用评测集中的差回答校准 |
| 语音识别不可用 | 一般 | 自动检测，降级为打字或系统听写 |
| API 调用失败或超时 | 一般 | 提示检查 API Key 和网络；出题失败时可使用内置通用题库 |
| JSON 格式错误导致页面无法显示 | 一般 | 解析失败自动重试一次，仍失败则显示原始文本 |

| 动作 | 级别 | 理由 |
|---|---|---|
| 搜索、出题、追问、评分 | L1 自动执行 | 只读，不影响用户的任何外部数据 |

## 11. 数据与隐私

| 检查项 | 处理 |
|---|---|
| API Key | 只保存在浏览器本地，只发送给用户选择的模型服务商 |
| 简历 | 可选填写；只用于本次出题和评分；页面提示"简历内容会发送给模型服务商，请去掉身份证号、电话等信息" |
| 作答记录 | 只保存在浏览器本地，可一键清除 |
| 服务器 | 本产品不设服务器，不收集任何数据 |
